# План разработки hl-trader

Проект делится на четыре этапа по контрольным точкам. Каждая задача ссылается на требования SRS (FR/NFR) и тест-кейсы RTM (TC), поэтому по плану видно, какая часть RTM уже закрыта.

## Процесс

- Ветки по GitHub Flow: `main` всегда рабочий, каждая задача в своей ветке `feat/<задача>` и уходит в `main` через pull request.
- На каждый PR CI запускает `ruff`, `mypy` в строгом режиме и `pytest`. PR с красным CI не сливается.
- Тесты называются по ID тест-кейсов RTM (`test_tc_3_1_...`), и `pytest -k tc_` запускает только их.
- Пороги, веса и границы нормировки лежат в `src/hl_trader/domain/methodology.py` под общим номером версии (FR-8, FR-13, NFR-4).
- Доменная логика не ходит в сеть и в БД, поэтому ее тестируют на эталонных данных, а пересчет не обращается к бирже.
