# hl-trader

Формат Lenny.

Сервис показывает частному криптотрейдеру и его ИИ-агенту, за какими трейдерами HyperLiquid стоит следить, почему именно за ними и сколько данных стоит за этим выводом, а сделки выбранных трейдеров присылает в Telegram.

## Description

Сервис регулярно собирает публичные данные трейдеров HyperLiquid, отсеивает тех, кому нельзя доверять, а оставшимся ставит оценку качества по нескольким метрикам. Рядом с оценкой стоит отдельное число, уверенность, которое показывает, сколько данных за ней стоит.

Результат доступен в трех местах: веб-рейтинг с карточкой трейдера, Telegram-бот с подпиской на сделки и пересмотр вывода, MCP-сервер, через который ту же оценку запрашивает ИИ-агент.

## Problem

Частный трейдер хочет заходить в сделки вслед за сильными трейдерами и понимать, кому из них можно доверять. Официальный рейтинг HyperLiquid сортирует по заработанным долларам и проценту доходности, поэтому наверху оказываются и тот, кому повезло на одной сделке, и тот, кто рисковал всем счетом: ни просадок, ни числа сделок за результатом не видно. Отличить сильного от везучего трейдер может только вручную, листая сделки кошелька, и на одного кандидата уходит около часа.

Коммерческие сервисы эту задачу решают наполовину. Hyperdash и Nansen ставят оценку, но по закрытой формуле. Copin открыт, но итоговой оценки не дает. Ни один не говорит, на скольких сделках построен вывод, и ни один не объясняет, почему трейдер отклонен.

Для ИИ-агентов пробел больше: существующие MCP-серверы HyperLiquid дают цены, стакан и ордера, но ни одного инструмента для поиска трейдеров.

## Why

- ~$240 млрд -- оборот HyperLiquid за 30 дней, 36,5% оборота всех децентрализованных бирж бессрочных фьючерсов. Каждая сделка на бирже публична, то есть данные для отбора есть (CryptoRank, 17.09.2026).
- 97% трейдеров, за которыми копируют сделки, заработали сами, но только 44% принесли прибыль тем, кто за ними повторял. Заработок трейдера плохо предсказывает результат последователя (YieldFund, 2025; Binance, Bybit, MEXC; 1 486 трейдеров).
- 41 тыс. аккаунтов в публичном рейтинге HyperLiquid, отсортированных только по прибыли и доходности; вручную такой список не разобрать.
- ~1 час на ручной разбор одного кошелька.
- 0 инструментов поиска трейдеров в открытых MCP-серверах HyperLiquid: edkdev/hyperliquid-mcp, midodimori/hyperliquid-mcp.

## Success

| ID | Тип | Метрика | Цель | Как меряем |
| --- | --- | --- | --- | --- |
| M-1 | Главная | Медианная доходность отобранных трейдеров за 30 дней после отбора минус медианная доходность не прошедших отбор | > 0 минимум в 2 из 3 ежемесячных когорт | отчет проверки отбора |
| M-2 | Прокси | Время от открытия карточки до решения "подписаться / нет" | медиана <= 60 с (сейчас ~1 час) | юзабилити-тест, >= 5 трейдеров |
| M-3 | Прокси | Доля пользователей бота, у которых через 30 дней после первой подписки есть хотя бы одна активная подписка | >= 40% | журнал подписок бота |
| M-6 | Прокси | Число разных ИИ-агентов, вызывающих MCP-инструменты за неделю | >= 3 | журнал вызовов MCP |
| M-4 | Guardrail | Доля отобранных трейдеров, провалившихся по фильтрам в течение 30 дней после отбора | <= 20% | отчет проверки отбора |
| M-5 | Guardrail | Доля ответов биржи "превышен лимит" (HTTP 429) от всех запросов за сутки | <= 1%, ни одной блокировки | мониторинг |

M-4 показывает, не подталкивает ли рейтинг пользователей к плохим трейдерам: если отобранные массово проваливаются по фильтрам, рейтинг вредит. M-5 следит за самим сервисом, потому что без доступа к API биржи он не работает.

## Audience

1. Частный криптотрейдер. Торгует сам, держит на HyperLiquid от нескольких тысяч до десятков тысяч долларов, хочет следить за сильными трейдерами и учиться у них. Персона -- Миша, разработчик, торгует по вечерам. Сейчас он берет кошельки из топа рейтинга и вручную листает их сделки.

2. Разработчик торгового ИИ-агента. Ему нужен источник данных, который агент опрашивает сам и который вместе с оценкой отдает меру доверия.

3. Разработчик сервиса (внутренний пользователь) -- автор проекта, один человек. Калибрует веса и пороги, проверяет главную гипотезу и следит, чтобы сервис укладывался в лимит API биржи.

Non-goals:

- автоматическое копирование сделок и любые действия со счетом пользователя;
- доступ к кошельку пользователя, хранение его ключей;
- другие биржи, кроме HyperLiquid;
- мобильное приложение;
- оценка маркет-мейкеров и высокочастотных трейдеров: их сделки невозможно повторить, пока сигнал доходит до человека;
- инвестиционные рекомендации: сервис показывает качество трейдера и его действия, решение остается за пользователем;
- платные тарифы в MVP.

## What

- Отбор вместо сортировки. Фильтры отсеивают трейдеров с коротким стажем, малым числом сделок, маленьким счетом, заметной долей ликвидаций или слишком коротким удержанием позиций. Остальные получают оценку от 0 до 1 по доходности с поправкой на риск, отношению прибыли к убыткам, доле прибыльных сделок, просадке, средней доходности сделки и стажу.
- Уверенность отдельным числом. Растет с числом сделок и длиной истории счета, падает, если история неполная. В оценку не подмешивается.
- Веб-рейтинг отобранных трейдеров с оценкой, уверенностью и стилем торговли (внутри дня, свинг, позиционный). Можно отфильтровать по монете, стилю и минимальной уверенности.
- Карточка трейдера. Вклад каждой метрики в оценку, статус каждого фильтра, откуда такая уверенность, открытые позиции и история событий. Карточка открывается и для отклоненного трейдера: видно, какой фильтр он провалил.
- Открытая методика и проверка вперед. На отдельной странице опубликованы формула, веса и пороги. Там же отчет: как отобранные трейдеры показали себя за 30 дней по сравнению с не прошедшими.
- MCP-сервер с тремя инструментами: `find_traders` (поиск по монете, стилю, минимальной уверенности), `get_trader` (карточка), `get_trader_events` (что трейдер делал с момента X).
- Пересчет без повторной загрузки (для разработчика). Веса и пороги можно поменять и пересчитать все оценки по уже сохраненным данным, не обращаясь к бирже.
- Telegram-бот. Подписка на трейдера из карточки или по адресу. Уведомления об открытии, изменении и закрытии позиций и о пересмотре вывода. Отписка в одно нажатие. Как выглядит уведомление:

   ```
   0x7a3f...c210 открыл LONG BTC * $240k * плечо 3.2x
   swing * score 0.68 * confidence 0.35 (пока мало сделок)
   держит позицию в среднем 23 ч
   [Карточка] [Отписаться]
   ```

## Допущения, риски, открытые вопросы

- Лимит API биржи -- 1 200 единиц веса в минуту на IP, и это главный технический риск. Поэтому отбор идет от дешевых данных к дорогим (сначала публичный рейтинг, история сделок только для оставшихся), а число отслеживаемых трейдеров ограничено.
- Гипотеза может не подтвердиться (M-1 <= 0), и такой исход тоже считаем результатом. Тогда меняем веса и пороги, пересчитываем оценки по сохраненным данным и повторяем проверку.
- История счета приходит редкими точками, поэтому метрики по ней дают нижние оценки. Это учитывается в уверенности.
- Открытые вопросы: калибровка весов по данным M-1, не слишком ли жесткие фильтры, модель монетизации после MVP.

Релиз-критерий MVP: пройдены все тест-кейсы из RTM, и за неделю непрерывной работы p95 задержки уведомлений не превышает 30 с, а M-5 держится в целевом значении.
